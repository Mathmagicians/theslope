UI design system

Nuxt 4.3, Nuxt UI 4.3, Tailwind 4.1. Pages use Nuxt UI components; every shared UI value comes from the design system (ADR-018 Design System Owns Shared UI Patterns). This page says where the system lives, what each token family is for and which patterns are shared. A component's own layout lives in its header mockup and its COMPONENTS.<name> token.

Rules

  • A component binds a design-system token and passes domain props only. designSystemUsage.unit.spec.ts holds the rule list and reports a breach as file:line.
  • A token holds one rendered value, light and dark together. Two values are two tokens, named by where they are used.
  • A Nuxt UI component family gets a token, and an architecture rule, before its first use. A value that moves into a token moves at every site in the same change.
  • A .vue carries no <style> block and no raw utility class (the one exemption is the print CSS in app/pages/admin/allergies/pdf.vue). An animation is a --animate-* keyframe in main.css, reached through a token that also carries motion-reduce:animate-none.
  • The design system is the one reader of the layout's breakpoint: a value that follows the breakpoint is a responsive token, and behaviour reads breakpoint (isMd, measured) from the composable; the usage spec fails any other inject of it.
  • Specs assert usage and behaviour; a token's value is checked by eye in the package's visual check.

Shared patterns

Edit affordances

SurfaceBinding
Table row, card header, notes boxv-bind="BUTTONS.edit" + aria-label="Rediger": square ghost pencil
Form card, detail panel headerv-bind="BUTTONS.secondaryAction" + :color="COLOR.primary" + :icon="ICONS.edit", label "Rediger <navn>"
Line in a listv-bind="BUTTONS.remove" + aria-label="Slet": square ghost trash in the row's last column

The settings wheel is BUTTONS.settings with an aria-label; labelled actions beside it bind BUTTONS.secondaryAction. A button that opens a panel below it spreads BUTTONS.flipOpen(isOpen): a chevron that turns while the panel is open, and aria-expanded. A chevron on another icon slot binds the same turn through its owner's token.

Collapsible panels

A panel that opens and closes is a UCollapsible with its toggle outside it: a UButton spreading BUTTONS.flipOpen(isOpen), and the collapsible binds a COMPONENTS.collapsible kind for its spacing. The toggle and the other controls of a header are siblings in a plain row, so no button holds another. The chef calendar header in ChefCalendarDisplay.vue is the reference: tabs on the left, the chevron on the right, the body below. A title with its chevron shares COMPONENTS.collapsible.headerRow.

Separators

A rule with words on it is a USeparator with a label, bound to a COMPONENTS.separator kind; the moment line in a history (TicketChanges.vue) is the reference.

Alerts

<UAlert v-bind="ALERTS.<kind>">; the site adds :title, :description, an :icon override, :avatar, data-testid, a margin class.

Modifiers spread after a kind: withActions (buttons beside the text from md, below it on a phone), withCornerAction (one icon button in the top-right corner). A runtime choice picks between kinds (v-bind="ok ? ALERTS.success : ALERTS.error"). A site that adds to a kind's ui merges on top of it.

Tables

The empty state renders in the UTable #empty slot. A table bound to a dataset that reloads binds that dataset's loading: UTable's loading bar runs under the column headers while the rows stay. Its #loading slot, the spinning sync glyph and a line of text from the table tokens, fills a table that has no rows yet, so the empty state shows only once the data has answered. COMPONENTS.table.ui cells wrap between words and keep words, dates and e-mails whole; a dense variant per surface sits beside it (table.catalogUi, table.bookingUi, …). A data table wider than a phone scrolls inside its own box; table.historyUi keeps each row on one line, so a history scrolls sideways on a phone. A column sizes through its meta.class ({th, td}); COMPONENTS.masterDetail holds the master table's primaryColumn and compactColumn. A row that spans the table, the moment line in TicketChanges.vue, sets the first column's meta.colspan.td to the column count and binds table.spannedCell on the other cells. An #expanded row spans every column: in a table that scrolls sideways, its content keeps to the part of the box in view, sticky at the cell's inset and no wider than the box (table.gridUi and table.adminUsersUi make their box a size container on a phone; bookingGrid.expandedPanel holds the booking grid's guest form, adminUsers.expandedPanel the user's profile card).

Choice groups

URadioGroup and USwitch bind a COMPONENTS.choiceGroup shape (stacked, inline, single); the section heading above them takes TYPOGRAPHY.sectionSubheading.

Team tabs

A UTabs whose triggers render CookingTeamBadges binds COMPONENTS.teamTabs: the link variant, triggers that keep their full label, and a horizontal row that scrolls sideways when more tabs than fit. On a phone the trigger stacks ICONS.team over the compact badge (MyTeamSelector, COMPONENTS.myTeamSelector).

A cancelled dinner

A cancelled dinner reads as a past day struck through on every member surface: the calendar day binds the past circle with the cancelled strike (CALENDAR.day), a ticket and a grid cell's mode badge bind the cancelled faces of their own tokens, built from the same past-day colours and strike, the grid's column header carries the dinner state badge in the lock chip's place, and the booking form and the chef's card wear the cancel corner ribbon (getRibbonClasses).

Master-detail pages

A page or tab that sets a calendar or a list beside the item it opens binds LAYOUTS.masterDetailPage: on UPage :ui, or on its own containers through the same root, left and center slots. A phone stacks the master over the detail; from md the master takes a third of the row, never narrower than a week of the calendar's day circles, and the detail takes the rest, never wider. The calendar's day circle steps up a size at lg. A master table whose detail docks under its row on a phone mounts the detail through COMPONENTS.masterDetail.

Component layouts

A layout one component owns is drawn in that component's header and bound through the COMPONENTS key that carries its name; the header also names the visual check.

Brand rainbow

  • PANTONE_FAMILIES orders the families; RAINBOW_FAMILIES holds the eight stops and HERO (read as BACKGROUNDS.hero) pairs each fill with its ink. Til farveblinde publishes the Color Universal Design colours on the stops (scripts/palettes/presets.ts).
  • Mocha is the frame: title bar, ticker, app shell, dinner header.
  • The landing bands, the kitchen panels and the cooking teams walk the stops in order (getRainbowBand); a team wears the stop of its number and the ninth repeats the first.
  • A team's number is the one in its name ("Madhold N"), else its position in the season's team list (getTeamNumber in useCookingTeam); every site that shows a team takes its band from that number.
  • Mockups: app/pages/index.vue and app/components/dinner/KitchenPreparation.vue headers.

Palettes

  • Options. Glade farver (default, AA), Høj kontrast (high-contrast, AAA), Til farveblinde (colorblind, AA, colour-safe). PALETTES holds each key's level and colourSafe; UserPreferencesCard.vue renders the badges from them.
  • Mechanism. Glade farver is the base: palettes/default.css applies under html:not([data-palette]). A preset redeclares --color-<family>-<step>, --ui-<slot> and --ui-color-<slot>-<step> under html[data-palette="<key>"]. Each block has a .dark mirror and outranks the variables Nuxt UI writes at runtime. app/layouts/default.vue writes data-palette (omitted for default) and data-text-scale from the session user's appearance; SSR renders them.
  • Generator. scripts/palettes/presets.ts (data), render.ts (hue map, slot re-pointing, OKLCH lightness walk to the preset's level), generate.ts (CLI). Run after a change to the main.css scales, ui.colors or a token that adds a fill or an ink, and commit the output:
    make palettes            # npx jiti scripts/palettes/generate.ts
  • Checks (npx vitest run tests/component/architecture): designSystemContrast.unit.spec.ts measures every pair designSystemPairs.ts walks from the tokens in each committed palette file at its preset's level; designSystemColourVision.unit.spec.ts measures meaning pairs and rainbow stops under three vision types (ΔE ≥ 0.075 in Oklab); palettes.ts derives the measured list from PALETTES.
  • Preview in the browser console:
    document.documentElement.dataset.palette = 'high-contrast'   // 'colorblind'
delete document.documentElement.dataset.palette             // Glade farver
document.documentElement.classList.toggle('dark')
