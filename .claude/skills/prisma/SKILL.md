# Prisma and D1 migrations

The schema is the domain model; a migration is a one-shot, tracked step on three databases (local miniflare, dev, prod). The
Make targets own the file layout; the user owns every database write.

## Order of work

1. **Sign-off before schema.** Post the model change (the Prisma block, the migration's data lines, the columns' nullability and
   defaults) in the feature document and wait for the user's yes. Column choices are the user's: a column is required with a
   default unless the user decides otherwise; a "done" mark is a fact row, a content version sits on the aggregate.
2. **Edit `prisma/schema.prisma`**, then `npx prisma format` and `npx prisma validate`.
3. **The user runs `make d1-create-migration name=<change>`.** It writes `prisma/migrations/<stamp>_<change>/migration.sql`
   and flattens it to `migrations/NNNN_<last word of change>.sql` (`Makefile` `d1-flatten-migrations`: the name after the
   last underscore of the directory). Read both files; Prisma's diff is the source.
4. **Data lines go in the Prisma source only**, appended after Prisma's DDL, convergent so a re-execution changes nothing:
   `INSERT … SELECT … WHERE NOT EXISTS (…)`, `SET x = max(x, 1)`, a date literal for "rows that predate this migration".
   Then regenerate the copy: `rm migrations/NNNN_*.sql && make d1-flatten-migrations`. `migrations/` holds the files the
   target produced; a file written by hand there is the error this skill exists for.
5. **`make d1-prisma`** (format, validate, client, `prisma/generated/zod` — committed, ADR-001). Run it after every schema edit;
   the generated zod is what the validation composables import.
6. **Code follows the generated layer**: enums re-exported from a `use<Domain>Validation` composable, raw fixtures
   (`tests/e2e/testDataFactories/*`, spec literals) carry the new columns, `npm run ts` / `ts:server` green.
7. **The user applies**: `make d1-migrate-local` (then `nuxt dev` for the e2e specs), `make d1-migrate-dev` before
   `make deploy-dev`, `make d1-migrate-prod` before `make deploy-prod`.

## D1 facts (verified 2026-09-17)

- A migration file applies once per database (`d1_migrations` table); the DDL is one-shot, the data lines are written convergent anyway.
- `DateTime` is ISO-8601 text (`2026-06-16T22:00:00.000+00:00`); compare with a text literal.
- Prisma emits a table rebuild (`new_<Table>`, copy, `DROP TABLE`, rename) for every **required** column. On D1 the `PRAGMA foreign_keys=OFF` around it is a no-op inside the migration transaction, so `DROP TABLE` fires every child's `ON DELETE` action — `0015` as generated nulled every parent link on local and dev (2026-09-17). Rewrite the block in the Prisma source to `ALTER TABLE … ADD COLUMN … NOT NULL DEFAULT <constant>`; `tests/component/architecture/migrations.unit.spec.ts` rejects a `DROP TABLE` in any migration after `0014`.
- `make d1-migrate-<env>` compares the child-without-parent counts before and after the apply and fails on a change; `make d1-verify-<env>` prints them. A migration is done when that check is clean on local (a copy of dev: `make d1-copy-dev-to-local`), then on dev, then on prod.
- Enum values are text in JSON or enum columns; adding a value is a schema + zod change with no SQL.
- ADR-014 limits: 100 bound parameters per statement, 1 000 queries per invocation.

## Commands I run vs. commands the user runs

| I run | The user runs |
|---|---|
| `npx prisma format`, `npx prisma validate`, `make d1-prisma`, `make d1-flatten-migrations`, `make -n <target>` dry runs, `make d1-verify-<env>` and `wrangler d1 execute … --command "SELECT …"` (reads) | `make d1-create-migration`, `make d1-migrate-*`, `make d1-copy-dev-to-local`, `make d1-time-travel-dev|prod`, `make d1-seed-*`, `npm run db:*`, `wrangler d1 migrations apply`, `wrangler d1 time-travel restore`, `wrangler d1 export`, every `wrangler d1 execute` that writes, `wrangler d1 create|delete` — denied to me in `.claude/settings.json`; a guard is verified with `make -n`, never by running the target |

## Checklist before handing a migration over

- [ ] model signed off; every column's nullability and default decided
- [ ] Prisma source = diff + convergent data lines; flattened copy regenerated by the target and identical
- [ ] `make d1-prisma` run; generated zod committed; validation composable re-exports the new enums
- [ ] fixtures and spec literals updated; `npm run ts`, `ts:server`, unit green
- [ ] runbook "Schema Changes" procedure still matches the targets
